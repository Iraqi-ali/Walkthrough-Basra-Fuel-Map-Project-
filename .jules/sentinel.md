## 2026-07-01 - Source Code and Sensitive Data Disclosure via `SimpleHTTPRequestHandler`
**Vulnerability:** A custom HTTP handler extending `http.server.SimpleHTTPRequestHandler` passed all undefined routes to `super().do_GET()` without restriction. This exposed the entire repository, allowing attackers to download backend source code (`server.py`), internal states, and the primary dataset (`data.json`) which acts as the core persistent store.
**Learning:** `SimpleHTTPRequestHandler` is inherently insecure for application routing as it treats the working directory as the web root. Attempting to secure it via string matching is highly prone to bypasses (e.g., matching exact string `/data.json` can be bypassed using `/./data.json` or `//data.json` since the underlying handler normalizes paths automatically). (Note: Python's built-in handler automatically prevents escaping the cwd via `../`, so raw directory traversal out of the project root was not possible, but source disclosure within the root was).
**Prevention:** To secure custom `SimpleHTTPRequestHandler` implementations, you must normalize the path (`posixpath.normpath(urllib.parse.unquote(path))`) and strip excess slashes *before* applying security checks. A robust blocklist targeting sensitive extensions (`.py`, `.log`) and critical state files (`data.json`) prevents source code disclosure without the brittleness of a strict allowlist.
