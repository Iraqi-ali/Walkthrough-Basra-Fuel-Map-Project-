## 2024-05-24 - SimpleHTTPRequestHandler Sensitive File Exposure and Path Traversal bypass
**Vulnerability:** SimpleHTTPRequestHandler by default serves all files in the current directory and subdirectories, exposing sensitive files like backend source code (`server.py`), configuration or database files (`data.json`, `reports.json`, `visitors.json`), and log files (`server.log`). Additionally, basic prefix path blocking (e.g., `not path.startswith('/api/')`) or relying solely on `posixpath.basename` without resolving dot segments and `//` can lead to path traversal vulnerabilities. Attackers can bypass blocklists using dot-dot-slash sequences (e.g., `/api/../server.py`) or by prepending multiple slashes to evade prefix checks (e.g., `//server.py`).

**Learning:** When using Python's `SimpleHTTPRequestHandler` (which extends `BaseHTTPRequestHandler`), both `do_GET` (file content exfiltration) and `do_HEAD` (metadata exfiltration) must be securely overridden. Path validation must occur before serving any file. Bypassing validation based on string prefixes (e.g. `/api/`) creates path traversal vulnerabilities if `.`, `..`, or `//` exist in the path. You cannot rely on `urllib.parse.urlparse(path).path` for validation since paths starting with `//` (e.g., `//server.py` or `/%2fserver.py`) are parsed as a network location (`netloc`), resulting in an empty path and bypassing blocklists. The resolved absolute path should also not be evaluated for hidden directories (e.g., `resolved.split(os.sep)`), as this erroneously blocks all access if the server is deployed inside a hidden parent directory (e.g., `/.jenkins/`).

**Prevention:** Always normalize the path before extracting the filename for validation. Implement a strict, unconditionally applied blocklist by explicitly parsing the original unquoted URL path (e.g., `urllib.parse.unquote(path).split('/')`) to detect hidden segments or sensitive files by exact name (e.g., `data.json`, `reports.json`, `server.py`). Iteratively replace `//` with `/`, and explicitly strip query parameters and fragments using `.split('?')[0].split('#')[0]`. Do not use blanket blocklists on common extensions like `.json` to prevent breaking legitimate frontend requests. Both `do_HEAD` and `do_GET` must apply this validation logic.
