## 2024-09-13 - Path traversal and sensitive file exposure in SimpleHTTPRequestHandler
**Vulnerability:** The SimpleHTTPRequestHandler allowed accessing arbitrary hidden files (e.g., .git/config) and backend code/data files (server.py, data.json) because path validation was not performed on static file requests, and path resolution allowed bypassing simple blocklists using `//` or URL encoding.
**Learning:** In Python's SimpleHTTPRequestHandler, any path not explicitly handled in do_GET will by default serve local files from the working directory. It is critical to sanitize and explicitly block sensitive files and hidden paths. Furthermore, do_HEAD must also be protected as it could leak metadata about the existence and size of files. `urllib.parse.urlparse(path).path` is insufficient because paths like `//server.py` are parsed as a network location (`netloc`), resulting in an empty path and bypassing validation.
**Prevention:** Always unquote URL paths, normalize multiple slashes (e.g., iteratively replace `//` with `/`), and explicitly split off query parameters and fragments before validation. Explicitly block hidden segments (starting with `.`) and sensitive file names. Protect both do_GET and do_HEAD methods.
