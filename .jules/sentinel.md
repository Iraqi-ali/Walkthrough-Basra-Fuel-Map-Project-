## 2026-08-28 - Information Disclosure via Missing File Access Controls
**Vulnerability:** The `SimpleHTTPRequestHandler` in `server.py` falls back to serving any file on the filesystem via `super().do_GET()` for paths that don't match `/` or `/api/*`. This allows attackers to easily access sensitive backend code (`server.py`), configuration/state (`reports.json`, `visitors.json`), and potentially navigate to other directories using path traversal (`../`).
**Learning:** `SimpleHTTPRequestHandler` is inherently insecure for production use unless its file serving capabilities are strictly constrained. Relying on default behavior without an explicit blocklist (or allowlist) leaves the entire server directory (and potentially more) open to information disclosure. A blocklist is needed for our specific use case, and both `do_GET` and `do_HEAD` must be secured. Furthermore, we must evaluate the *resolved* path (using `translate_path`) to prevent path traversal bypasses.
**Prevention:** Always restrict direct file access when using `SimpleHTTPRequestHandler` by implementing a robust, explicitly defined blocklist or allowlist on the resolved file path before calling the parent handler, and ensure both GET and HEAD methods are protected.
