## 2026-11-01 - SimpleHTTPRequestHandler Path Traversal and Data Disclosure
**Vulnerability:** The application was serving the entire directory by default via `SimpleHTTPRequestHandler`. Unrestricted `do_GET` allowed attackers to download the server source code (`server.py`) and sensitive runtime data (`data.json`, `reports.json`, `visitors.json`), and potentially perform path traversal. A secondary vulnerability (Parser Differential) existed where stripping query strings manually using `.split("?")[0]` failed to account for `#` fragments, allowing an attacker to bypass the path blocklist by requesting `/server.py#`.
**Learning:** `SimpleHTTPRequestHandler` serves all files in the current directory unless explicitly restricted. When implementing an API over it, any unhandled path falls back to `super().do_GET()`, exposing all local files. Also, relying only on `do_GET` restrictions leaves `do_HEAD` vulnerable to metadata leakage or existence checks of sensitive files. Finally, manual URI parsing often misses edge cases like URL fragments (`#`), creating parser differentials compared to standard library parsers.
**Prevention:** Implement an explicit allowlist or blocklist for paths falling back to the standard static file handler. Always validate and sanitize `self.path` by fully parsing it with `urllib.parse.urlparse` to safely isolate the `.path` component before applying URL decoding (`unquote`). Always override `do_HEAD` to mirror the security restrictions of `do_GET`.
