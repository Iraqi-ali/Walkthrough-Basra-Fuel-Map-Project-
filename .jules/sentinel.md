## 2026-10-06 - Path Traversal Vulnerability in SimpleHTTPRequestHandler
**Vulnerability:** The Python `SimpleHTTPRequestHandler` implicitly served any file on disk, including source code (`server.py`), internal data (`reports.json`, `visitors.json`), and hidden directories (`.git/`). Attackers could use path traversal (e.g., `/%3F/../`) to bypass naive blocklists on `self.path` because URL query strings were ignored by the `translate_path` method but not explicitly checked. Furthermore, both `do_GET` and `do_HEAD` could expose file data or metadata.
**Learning:** `SimpleHTTPRequestHandler` requires an explicit, whitelist-oriented path validation strategy. Because `curl` normalizes paths unless `--path-as-is` is given, it's easy to miss parser differential bypasses (like `/%3F/../`) that trick the server. The absolute path (`local_path = self.translate_path(self.path)`) must be used for all access checks, rather than trying to parse `self.path` directly.
**Prevention:** Override both `do_GET` and `do_HEAD`. Resolve the request path to a concrete local path using `self.translate_path(self.path)`, then validate its components relative to the working directory using `os.path.relpath`. explicitly block restricted extensions or directories to ensure only safe, intended assets are served.
