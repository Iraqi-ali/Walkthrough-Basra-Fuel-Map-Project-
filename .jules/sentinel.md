## 2026-09-24 - SimpleHTTPRequestHandler Path Traversal and Sensitive File Exposure
**Vulnerability:** The Python `http.server.SimpleHTTPRequestHandler` serves all files in the current directory by default if they don't match specific API paths. This allowed any user to download `server.py`, `data.json`, and potentially other sensitive files by simply requesting them by name. Furthermore, attempting to manually parse and filter the URL string introduces parser differential bypasses (e.g., using `/%3F/../` bypasses naive checks while the underlying base handler properly resolves to the blocked file).
**Learning:** Extending `SimpleHTTPRequestHandler` without explicitly blocking or restricting the static file serving capability can unintentionally expose the entire backend source code and internal state files. Replicating built-in URL parsing logic manually is dangerous and error-prone.
**Prevention:** When using `SimpleHTTPRequestHandler` for static assets and an API, always implement a strict allowlist of serveable files (like `.html`, `.js`, `.css`) or explicitly blocklist known sensitive extensions (`.py`, `.json`, `.log`, `.env`) and dotfiles. Always use the built-in `self.translate_path(self.path)` to determine the final resolved local filesystem path before performing security checks, which guarantees the check evaluates exactly what the handler will load.
