## 2026-09-07 - Python SimpleHTTPRequestHandler Path Traversal & Sensitive File Exposure
**Vulnerability:** The custom HTTP server using `SimpleHTTPRequestHandler` implicitly served sensitive backend files (`server.py`, `data.json`, `reports.json`, `visitors.json`) and exposed hidden files due to insufficient path validation in `do_GET` and `do_HEAD`.
**Learning:** When inheriting from `SimpleHTTPRequestHandler`, overriding specific paths (like `/api/`) while falling back to `super().do_GET()` for everything else leaves the server wide open to directory traversal and direct access to source/data files. Furthermore, attackers can use `curl -I` (HEAD requests) to bypass `do_GET` checks if `do_HEAD` is not also secured. Path checks must operate on unquoted and correctly resolved paths to prevent `/api/../blocked_file` bypasses.
**Prevention:** Always implement an explicit blocklist or allowlist for paths handled by `super().do_GET()`. Ensure `do_HEAD` is also overridden and secured alongside `do_GET`. Use robust path parsing (like `urllib.parse.urlparse` and unquoting) rather than simple string prefix checking to defend against traversal attacks.
