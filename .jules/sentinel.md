## 2026-11-03 - Path traversal and source code disclosure via SimpleHTTPRequestHandler
**Vulnerability:** The server was exposing sensitive source code (`server.py`), internal JSON data files (`reports.json`, `visitors.json`), and potentially hidden directories (`.git/`) because `SimpleHTTPRequestHandler` serves any file by default when the path isn't explicitly intercepted by custom `do_GET` handling.
**Learning:** Python's `SimpleHTTPRequestHandler` must be explicitly restricted. Relying solely on `do_GET` interception for specific API paths leaves the entire filesystem open to path traversal or standard file fetching. Additionally, preventing bypasses using url parsing (`urllib.parse`) requires correctly handling double slashes (`//`) as they get parsed into the network location (`netloc`), and unquoting to prevent URL encoded variants (`%2e%2e`). Finally, overriding only `do_GET` is insufficient as `do_HEAD` must also be overridden to protect sensitive files from metadata extraction or existence checking.
**Prevention:** Always implement an explicit access control layer (`_check_access`) that evaluates and normalizes the parsed, unquoted requested path (`self.path`) and strictly returns 403 Forbidden for hidden files and sensitive tracked configuration files in both `do_GET` and `do_HEAD`.
