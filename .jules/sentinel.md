## 2026-11-09 - SimpleHTTPRequestHandler Path Traversal Bypass
**Vulnerability:** SimpleHTTPRequestHandler by default allows serving all files in the current directory and subdirectories. While overriding `do_GET` to restrict specific paths is common, it's often implemented insecurely by not overriding `do_HEAD` (allowing file discovery/metadata leakage) or by using simple string matching that can be bypassed using double slashes (e.g., `//server.py`), URL encoding (e.g., `/%73erver.py`), or directory traversal sequences (e.g., `/../server.py`).
**Learning:** Python's standard `http.server.SimpleHTTPRequestHandler` is intended for basic file serving, not production security. Custom security logic overlaid on it must account for HTTP method completeness (securing both GET and HEAD) and rigorous path normalization before authorization checks. Specifically, parsing URL paths must handle `//` bypasses where `urlparse` misinterprets it as a network location (`netloc`), then decode, collapse slashes, and normalize with `posixpath.normpath()`.
**Prevention:** When extending standard HTTP handlers, implement access control logic in a reusable method and apply it strictly to all relevant request methods (e.g., `do_GET`, `do_HEAD`, `do_POST`). Always normalize paths using `urllib.parse.urlparse`, `urllib.parse.unquote`, and `posixpath.normpath` while explicitly handling the double-slash netloc edge case before evaluating the path against blocklists or allowlists. Never rely on raw string matching for URL paths.
