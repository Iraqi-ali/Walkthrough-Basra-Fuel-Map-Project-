## 2026-09-21 - Fix path traversal and sensitive file exposure in SimpleHTTPRequestHandler
**Vulnerability:** The SimpleHTTPRequestHandler exposed source code (server.py) and sensitive backend state files (reports.json, visitors.json) because it lacked explicit path validation and allowed dot-dot-slash sequence traversals (e.g. /api/../server.py). Furthermore, only do_GET was investigated natively, leaving do_HEAD completely vulnerable.
**Learning:** Overriding do_GET to proxy requests for API routes does not inherently secure static file serving fallbacks (super().do_GET()). Using URL path prefixes is bypassable with path traversal (..), and urllib.parse.urlparse is unreliable as it parses paths beginning with '//' as network locations, effectively bypassing validations. Additionally, SimpleHTTPRequestHandler responds to HEAD requests separately, completely circumventing custom logic placed only in do_GET.
**Prevention:** Always normalize paths using posixpath.normpath and properly replace '//' sequences before implementing a blocklist based on posixpath.basename. Both do_GET and do_HEAD must be explicitly secured or explicitly disabled to prevent metadata exposure.
